# 04 数据模型

表定义全部在 `backend/app/models.py`，主键为自增 `id`，外键一律 `ON DELETE CASCADE`。新库由 `database.init_schema()` 建表，老库列变更写在 `app/migrations.py` 启动时增量执行。

| 表 | 用途 | 关键字段与约束 |
| --- | --- | --- |
| `repos` | 仓库接入配置 | `platform`（gitea/gitee）、`owner/repo/base_url`、`token_enc`（加密令牌）、`include/exclude_keywords`、`enabled`、最近同步状态三件套（`last_sync_at/status/message`） |
| `commits` | 已入库提交 | `repo_id` + `sha` 唯一；`message/author_*`、增删行数、`files_json`（变更明细 JSON）、`committed_at` |
| `repo_authors` | 同步见过的作者候选 | `repo_id` + `identity` 唯一；含未入库的他人，用于「我的作者标识」候选 |
| `work_entries` | 手工工作记录 | `work_date`、`title/content/category/project/tags`、`hours` |
| `reports` | 生成的报告 | `period_type`（weekly/monthly/quarterly/yearly/custom）、`start_date/end_date`、`status`、生成进度三件套 `stage/progress/error`、`content/stats_json/source_json/model` |
| `projects` | 项目字典 | `name` 唯一；`source`（manual/auto） |
| `review_tasks` | 审查任务 | `repo_id`、`status`（pending/running/completed/cancelled/failed）、`limit`、`only_new`、`total/processed/finding_count`、`model/message` |
| `code_reviews` | 单提交审查结果 | `task_id`（可空）、`repo_id`、`commit_sha/subject/url/author_name`、`status`、`finding_count` |
| `review_findings` | 审查发现的问题 | `review_id`、`file_path/line/severity/category/title/detail`、`status`（pending/ignored）、推 Issue 后记 `issue_number/issue_url` |
| `monitors` | 监控目标 | `url/health_path/method/expect_status/keyword`、`interval_minutes/timeout`、`enabled/alert_enabled`、最近状态（`last_status/last_check_at/last_latency_ms/last_error/fail_count`）、累计检查数 |
| `monitor_checks` | 探活流水 | `monitor_id`、`status/status_code/latency_ms/error/checked_at` |
| `app_settings` | 运行配置键值 | `key` 主键 + `value`，经 `services/config_store.py` 读写（大模型、企微 webhook、同步间隔、作者标识等） |

## 使用要点

- 时间字段一律本地业务时区（`models.utcnow` → `timeutil.now_local`）；`reports` 等按日期统计用 `Date` 字段。
- 级联删除已配好（删仓库连同提交、审查、作者候选；删审查连同 findings；删监控连同流水），写删除逻辑时依赖 ORM cascade，不要手工逐表删。
- 想加表：先在 `models.py` 定义，再确认 `init_schema` 能建；给已有表加列则必须同时写 `migrations.py` 的增量迁移并给默认值。

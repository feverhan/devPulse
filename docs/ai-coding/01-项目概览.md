# 01 项目概览

## 产品定位

研发脉冲（Dev Pulse）是面向研发的个人工作台：

- 汇总 Gitea / Gitee 提交与手工登记的工作记录，一键产出周报、月报、季报、年报；
- 对提交做代码质量审查（LLM），并把问题推送为仓库 Issue；
- 对内部服务定期探活，异常时经企业微信告警。

默认本地 SQLite，开箱即用；报告与审查接 OpenAI 兼容大模型（vLLM / Ollama / LM Studio 均可），未配置或调用失败时自动回退本地模板。

## 功能模块

| 模块 | 后端路由 | 前端页面 | 说明 |
| --- | --- | --- | --- |
| 认证 | `auth` | LoginView | 访问密码登录；未设置密码时不启用 |
| 初始化向导 | `setup` | SetupView | 数据库 / 大模型 / 访问密码三步，可跳过 |
| 仓库 | `repos` | ReposView | 粘贴地址自动解析平台与拥有者；令牌加密存储 |
| 提交 | `commits` | CommitsView | 同步入库的提交列表与统计 |
| 项目 | `projects` | ProjectsView | 项目字典，可手工建，也可从同步的提交自动聚合 |
| 工作记录 | `works` | WorksView | 手工登记日期、标题、类别、项目、工时 |
| 报告 | `reports` | ReportsView | 后台生成，SSE 实时回显阶段与正文 |
| 代码审查 | `reviews` | ReviewsView | 后台逐提交审查，问题可单条/批量推 Issue |
| 服务监控 | `monitors` | MonitorsView | 周期探活，状态跃迁时企微告警 |
| 概览 | `dashboard` | DashboardView | 工作量与提交统计 |
| 设置 | `settings` | SettingsView | 大模型、同步、告警、数据迁移与备份 |

## 关键业务规则

改功能时不要破坏这些既有规则：

1. **只汇总自己的提交**：「设置 → 同步 → 我的作者标识」填姓名 / 登录名 / 邮箱（逗号分隔），同步时跳过他人提交；再次同步会清理此前已入库的他人提交。作者候选来自 `repo_authors` 表（同步时见过的全部作者），不是只看已入库提交。
2. `Merge` / `Revert` 开头的提交说明不计入统计。
3. 提交同步按仓库配置的「包含关键字 / 排除关键字」过滤，分页拉取并按 `(repo_id, sha)` 去重。
4. 报告生成是后台任务：阶段进度与正文实时写入 `reports.stage / progress / content`，前端经 SSE（`GET /api/reports/{id}/stream`）读取；进程重启后残留「生成中」的报告标记为失败，另有每分钟的超时清扫。
5. 代码审查只保留客观缺陷（逻辑错误、异常未处理、资源泄漏、并发、安全、性能），风格建议排除；推 Issue 走平台 API。
6. 服务监控首次检查不告警，此后状态跃迁才推送（正常→异常报障，异常→正常报恢复）。
7. 仓库令牌用主密钥（`secret.key`）加密存储；导出 JSON 备份自带主密钥，跨机器导入后令牌仍可用。
8. 数据库切换（SQLite ↔ MySQL）先试连再切换，失败不动原库；迁移复制全部业务表。

## 部署形态

- 源码开发：uvicorn + vite dev server；
- 容器：Docker Compose / Podman（默认 SQLite，可选自带 MySQL 的 compose 文件）；
- 免容器发布：PyInstaller 单文件 `devpulse.exe`（图形启动器）+ `devpulse-cli.exe`，打包脚本 `scripts/standalone/build.ps1`。

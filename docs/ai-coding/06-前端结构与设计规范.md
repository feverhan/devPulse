# 06 前端结构与设计规范

## 技术与结构

Vue 3 + TypeScript + Vite，UI 用 Element Plus，状态 Pinia，路由 vue-router（`createWebHistory`）。

```
src/
  main.ts / App.vue
  router/index.ts        # 路由表 + 全局守卫
  api/                   # client.ts（axios 实例）、index.ts（接口函数）、types.ts
  stores/                # auth（会话）、setup（初始化状态）等
  layouts/DefaultLayout  # 登录后主布局（侧边导航）
  views/                 # 每个功能一个页面，见下表
  components/            # 通用组件（TrendChart）
  utils/format.ts        # 时间、数量格式化
```

## 页面与路由

| 路径 | 页面 |
| --- | --- |
| `/setup` | 三步初始化向导 |
| `/login` | 登录 |
| `/dashboard` | 概览 |
| `/repos` `/commits` `/projects` `/works` | 仓库 / 提交记录 / 项目 / 工作记录 |
| `/reports` | 报告 |
| `/reviews` | 代码审查 |
| `/monitors` | 服务监控 |
| `/settings` | 设置 |

路由守卫（`router/index.ts`）：

1. 首次导航先 `auth.check()` 确认会话；
2. 需要密码且未登录 → 跳 `/login`（带 redirect）；
3. 拉取初始化状态：未初始化强制进 `/setup`，已初始化时 `/setup` 跳回 dashboard。

## 接口约定

- 统一经 `api/client.ts` 的 axios 实例；新接口在 `api/index.ts` 加函数、`api/types.ts` 加类型，不要在组件里散着 new axios。
- 后台任务型接口（报告生成、审查）遵循「POST 创建 → 轮询或 SSE 拿进度」的模式，报告用 SSE（`EventSource`），审查轮询任务详情。

## 页面设计约束（必须遵守）

**列表页头部不加标题、描述性文字和统计卡片。**

**卡片左侧不加颜色条。**

## 前端文案规则（必须遵守）

页面不得出现「操作指导型」文案。判断标准：这句话删掉后，用户是否会因此做错事？不会 → 删除。

禁止出现：

- 操作引导：如「勾选后可批量通过」「单击选中，双击载入」
- 状态复述：如「当前共 8 条数据」
- 校验前警告：如「请先勾选再点击」——正确做法是直接禁用按钮
- 空态说教：如「暂无数据，请稍后再试或联系管理员」
- 功能自夸：如「支持多维度组合筛选，精准定位」

允许保留：

- 业务内容：状态、风险等级、处置建议
- 事实反馈：有勾选行为时的「已选 3 条」
- 补救指引：操作真的走不通时告知原因和下一步

## 构建与托管

- `npm run dev` 走 Vite dev server；`npm run build` 产物在 `frontend/dist`，后端打包时复制为 `static/` 由 FastAPI 托管。
- 提交前端改动前跑 `npm run typecheck`。

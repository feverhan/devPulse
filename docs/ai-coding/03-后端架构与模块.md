# 03 后端架构与模块

## 请求生命周期

`app/main.py`：

1. `lifespan` 启动时：`init_schema()` 建表 → `_bootstrap_defaults()` 写默认配置 → 重置上次中断的审查任务与「生成中」报告为失败 → 启动 APScheduler → 启动两个后台 worker 队列（`default`、`report`）。
2. 挂载全部 router（均挂 `/api/...`），除 `auth` 外都依赖 `deps.require_auth`。
3. `GET /api/health` 免登录。
4. 若存在前端构建产物 `static/`，按 SPA 方式托管：非 `api/` 路径全部回退 `index.html`；单文件打包时静态资源在 `sys._MEIPASS/static`。

## 分层

```
routers/   只做出入参转换与权限依赖，业务交给 services
services/  业务实现，一个领域一个文件
models.py  SQLAlchemy 表定义
schemas.py Pydantic 出入参
```

## services 职责速查

| 文件 | 职责 |
| --- | --- |
| `gitplatform.py` | Gitea / Gitee 客户端：列提交、取 diff、建 Issue；`platform` 取值 `gitea` / `gitee` |
| `repo_url.py` | 解析 `https://` / `git@` 仓库地址，得到平台、实例根地址、owner、repo |
| `sync.py` | 同步提交：分页拉取、关键字过滤、作者标识过滤、去重入库、维护 `repo_authors` |
| `report.py` | 报告生成：收集提交与工作记录 → LLM 或模板 → 分阶段写进度 → 超时清扫 |
| `review.py` | 审查任务：逐提交取 diff 调 LLM，落 `code_reviews` / `review_findings`，推 Issue |
| `monitor.py` | 探活执行、健康路径自动探测、状态跃迁判断、企业微信 webhook 告警 |
| `llm.py` | OpenAI 兼容调用封装；地址缺 `/v1` 自动补全；超时与失败回退 |
| `config_store.py` | `app_settings` 键值配置读写与默认值 |
| `task_queue.py` | 进程内 asyncio 队列 + worker，`submit(fn, name)`；重启后 pending/running 任务标失败 |
| `scheduler.py` | APScheduler：按配置间隔同步仓库（最小 5 分钟）、巡检到期监控、每分钟清扫超时报告 |
| `migrate.py` | 换库 / 导入导出 JSON（导出带主密钥）/ SQLite 迁移，先试连后复制 |

## 鉴权与安全

- 访问密码可开关：`services/security.password_enabled(db)` 为假时全部接口放行。
- 登录成功签发签名会话 cookie（`SESSION_COOKIE`），`deps.require_auth` 校验。
- 仓库令牌用主密钥（`.env` 的 `APP_SECRET` 或数据目录 `secret.key`）加密后存 `repos.token_enc`。

## 后台任务与进度回显

- 审查与监控检查走 `default` 队列，报告生成走 `report` 队列，避免互相阻塞。
- 报告进度直接更新 `reports.stage / progress / content`，前端经 SSE 流读取；改报告逻辑时保持「阶段 + 进度 + 正文可续读」的结构。
- 任务状态只存数据库（`review_tasks.status`），队列本身不持久化；进程重启靠 `main.py` 的重置逻辑兜底。

## 数据库与迁移

- `database.init_schema()` 用 `Base.metadata.create_all` 建新表。
- 已有库的列变更写在 `app/migrations.py`（启动时按需 ALTER），不要依赖外部迁移工具。
- 切换数据库连接串运行时生效（`setup` 路由），`config_store` / `migrate` 负责落地与搬数据。
